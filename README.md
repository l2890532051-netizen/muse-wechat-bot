# muse-wechat-bot：让 Muse 住进你的微信

**中文** | [English](README.en.md)

一个自包含的「技能文件」，能把你自己的 Muse 通过腾讯官方 iLink Bot 接口接进微信：
扫一次码绑定之后，你在微信里聊到的就是你的 Muse 本人——同一套记忆、同样的工具和
技能，而不是另一个陌生的机器人。你出门在外、手机不离手的时候，掏出微信就能继续
跟它说话、派活、收结果。

## 它能干什么

绑定完成后，在微信里你可以直接：

- **聊天**：跟平时在 Muse 里一样对话，它记得你的长期记忆、目标和偏好，
  微信和主聊天两边互通——在微信里交代的事，回主聊天它也知道。
- **派活办事**：查资料、读链接、记提醒、刷新你的空间、整理信息……它有手有脚，
  能在微信里接任务、在后台做完、再回微信汇报。
- **发图片、视频、文件**：让它生成一张图、一段视频，或者把某个文件发给你，
  都能直接出现在微信对话里；你发给它的图片、视频、文件它也能收到并处理。
- **发语音**：微信语音会被转成文字交给它（没有转写时会明确提示你打字，
  不会装作听到了）。
- **发链接给它读**：转发一篇文章链接，它会读原文给你总结；实在读不到原文时
  会如实说明并转交主会话的浏览器去读，绝不用搜索拼凑的二手摘要冒充原文。
- **主动找你（可控）**：有紧急且有时效的事时，它可以不等你先说话、直接给你
  发微信；范围由你定——只推紧急事项，或者日常贴心的小提醒也可以，
  部署时跟它说清即可。
- **（可选）微信聊天日报**：每晚把当天在微信里聊的内容汇总成一页日报，
  方便回看，技能文件里留好了实现要点。

## 它不是什么（先把预期对齐）

- **不是群机器人**：只服务扫码绑定的你本人，只处理你的私聊；群聊和陌生人
  消息会被忽略（这是写死的白名单，想放开要你自己明确拍板）。
- **不是协议破解/外挂**：它走的是腾讯官方开放的 iLink Bot 接口
  （即微信 ClawBot 插件所用的同一套官方协议，文档见腾讯官方仓库
  [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)），
  不逆向、不 Hook、不模拟登录，封号风险远低于野路子方案——但请仍然看完
  下面的免责声明。
- **不是秒回**：消息接收是实时的，但生成回复需要唤醒 Muse，
  实测延迟约 30–60 秒，属于"对方正在输入"的体感，不要按即时通讯期待它。
- **不替你点确认**：付款、对外发送、扫码登录其他服务这类需要你在 App 里
  确认的步骤，它在微信里做不了，会引导你回主聊天处理。

## 工作原理（30 秒版）

```
你的微信 ⇄ 腾讯官方 iLink 接口 ⇄ bridge.py（一条 Python 小桥，常驻守护）
                                  ⇄ 本地队列（SQLite）
                                  ⇄ 事件钩子：每 5 秒只看一眼本地队列
                                     ——没消息，什么都不发生（零成本）；
                                     ——有消息，才唤醒 Muse 本人来处理
                                  ⇄ Muse 回复/办事 → 经桥发回微信
```

三个关键设计，也是这个 v2 版的立身之本：

1. **零空转成本**：老方案是"每分钟唤醒 AI 问一次有没有新消息"，没消息也在
   烧额度。本版用本地脚本轮询本地队列，空转时不唤醒 AI、不消耗任何额度，
   只有真有消息才花钱。维护者实测：重度使用一整天（十几轮微信对话 + 大量
   主聊天工作），Muse 的周额度约多消耗 1%；闲置时为 0。（你的实际消耗
   取决于你的套餐与用量，此为参考值。）
2. **原子认领**：消息被取走处理时会被"认领"锁定，杜绝同一条消息被回复
   两遍；处理进程中途死掉，10 分钟后自动回队，不丢消息。
3. **诚实红线**：唤醒提示词里写死了几条规矩——解释现象前必须先核查、
   不许编造原因；发送以前生成过的图片/视频必须如实说是现成的，不许冒充
   刚做的；事实类问题先联网核实再回答。这些都是真机踩坑换来的。

## 快速开始（真的只需要三步）

**前提**：一个能正常使用的 Muse；一台长期在线的机器（Muse 自带的云端
运行环境就可以，自己的 VPS 更好）；手机微信版本需支持 ClawBot 插件
（iLink Bot 通道由腾讯于 2026 年 3 月开放）。

1. **拿到技能文件**：下载本仓库的
   [`muse-wechat-bot-v2.md`](muse-wechat-bot-v2.md)（英文版：
   [`muse-wechat-bot-v2.en.md`](muse-wechat-bot-v2.en.md)），
   或者直接把文件链接发给你的 Muse。
2. **对 Muse 说一句话**：「按这个文件把你接进微信」。剩下的环境检查、
   部署、守护进程、钩子配置，全部由它代劳。
3. **你只做两件事**：① 它把二维码发给你时，用微信扫码并在手机上确认授权
   （二维码 5 分钟有效；偶尔会多一步"数字配对码"，把微信上显示的数字
   发给它即可）；② 绑定成功后，**在微信里先给它发一句话**（比如"你好"）——
   这是官方接口的铁律：没有会话，任何发送都会被拒绝。它回你了，就全部通了。

整个过程顺利的话约 10 分钟，其中你动手的时间不超过 1 分钟。

## 部署详细步骤（给想看明白的人）

以下每一步都由 Muse 自动完成，这里写出来是让你心里有数、方便验收：

| 步骤 | 做什么 | 你需要做什么 |
| --- | --- | --- |
| 0. 选机器 | 确认桥跑在哪台长期在线的机器上（VPS 最优，Muse 云环境次之，本机最差） | 无 |
| 1. 环境检查 | 检查 Python 3.8+，安装依赖 `requests`、`qrcode`、`pycryptodome`；测试接口连通性 | 无 |
| 2. 部署桥 | 把技能文件附录里的 `bridge.py` 源码原样落盘到 `~/wechat-bot/` 并通过语法校验 | 无 |
| 3. 扫码绑定 | Muse 取二维码、本地渲染成图片发给你；后台轮询授权状态；成功后 token 落盘 `~/wechat-bot/auth.json`（权限 600） | **扫码 + 手机确认**（可能要报一次数字配对码） |
| 4. 建立会话 | Muse 请你在微信里先发一句话，验证能收能回 | **在微信里发任意一句话** |
| 5. 守护与钩子 | 用 `launch.sh` 启动守护进程（长轮询收消息、媒体落盘、入队）；注册每 5 秒的本地事件钩子并写入唤醒提示词 | 无 |
| 6. 验收 | `bridge.py status` 显示守护存活；微信里实测一轮文字、一张图片的收发 | 瞄一眼微信确认收到 |

**安全须知**：`auth.json` 里的 token 是整条链路的钥匙，等同于这个微信
机器人身份的密码。桥会把它只存放在本机、权限 600；你也不要把这个文件
发给任何人、不要提交到任何仓库、不要在聊天里粘贴它。

## 部署完成后如何使用

- **日常聊天**：打开微信，找到这个对话（它在微信里的身份取决于 ClawBot
  插件的呈现方式），像跟朋友聊天一样说话即可。语气、记忆、能力都和主聊天
  一致，不需要学任何命令。
- **发任务**：直接说人话——"帮我查一下 X"、"把这个链接读一下总结给我"、
  "提醒我明天下午三点交材料"。它做完会在微信里汇报；需要你在 App 里
  点确认的步骤，它会说明让你回主聊天处理。
- **收发文件**：跟它说"把那张图发我"、"生成一个……发过来"，文件会直接
  进微信；你也可以直接把微信里的图片、文件、视频转发给它处理。
- **主动推送的范围**：想调整它"什么事可以主动发微信找你"，在主聊天里
  跟它说一句即可（比如"以后只有紧急的事才走微信"或"日常小提醒也可以"），
  它会记进你的偏好。
- **想停用**：让 Muse 停掉守护进程并删掉钩子即可彻底停止收发；
  想连根拔除，再删掉 `~/wechat-bot/` 目录，并在微信的 ClawBot 插件
  设置里解除授权。绑定关系不会自己过期，但停用后不会再有任何消息往来。

## 后期注意事项（运维清单）

- **主动推送的 24 小时窗口**：绑定不会过期，但**主动发送**依赖近期的会话：
  你超过约 24 小时没给它发过消息时，它主动发微信可能被服务端拒绝
  （你随便回它一句话，窗口立刻恢复）。这不影响接收和回复。
- **服务端暂停（-14）**：偶尔官方会暂停某个账号的会话 1 小时，守护进程会
  自动退避等待，不用管，也不要让 Muse 硬刷接口。
- **机器重启/重置**：钩子每轮都会顺带检查守护进程、死了自动拉活，云环境
  重置后能自愈；若长时间没反应，让 Muse 看一眼 `~/wechat-bot/bridge.log`。
- **日志与队列会慢慢变大**：`bridge.log` 和 `queue.db` 记录收发与回复，
  属于你的隐私数据，只存放在你自己的机器上；介意的话定期让 Muse 清理
  旧记录即可。
- **协议可能变**：iLink 是腾讯的官方接口，未来若调整，桥可能需要跟着
  更新；关注 [Tencent/openclaw-weixin](https://github.com/Tencent/openclaw-weixin)
  的更新，桥的协议层集中在 `bridge.py` 一个文件里，改起来不难。
- **不要两条链路并存**：钩子方案和"每分钟定时唤醒"方案只能留一个，
  两个一起跑会导致重复回复。
- **微信更新后先观察**：微信大版本更新偶尔会影响 ClawBot 插件可用性，
  更新后先发一句话测一下再依赖它传重要消息。

## 常见问题

- **回复为什么要半分钟？** 接收是实时的，慢在"唤醒 Muse + 生成回复"。
  这是为了零空转成本做的权衡。
- **能在群里用吗？** 不能（默认）。白名单只放行你本人的私聊。
- **换手机/换微信号了怎么办？** 重新跑一遍扫码绑定即可，桥和数据都在
  机器上，不受影响。
- **token 泄露了怎么办？** 在微信里解除 ClawBot 授权，删掉 `auth.json`，
  重新绑定生成新 token。
- **它说"发不了图片"？** 你装的可能是老版本桥。v2 已实现图片/视频/文件
  发送，让 Muse 按 v2 技能文件升级 `bridge.py` 即可。

## 与原版的差异（v2 改了什么）

v2 由本仓库维护者在真实部署并高强度使用一整天之后，针对原版逐项打磨，
核心改动（全部有实测依据，细节见技能文件开头的变更说明）：

1. 回复架构从"每分钟定时唤醒"改为"本地事件钩子 + 零空转成本"，
   并附钩子脚本与定义模板；
2. 补齐媒体**发送**（图片/视频/文件，走官方上传流程），原版只能发文字；
3. 入站媒体不再丢内容：视频、文件实际落盘，多图路径全记录，
   无转写语音有明确标记；
4. `inbox-new` 改为原子认领（防重复回复）+ 超时自动回队（防丢消息），
   新增只读计数的 `inbox-peek`；
5. 修复二维码获取：接口返回的是二维码内容链接，需本地渲染成图，
   原版处理方式实际拿不到可扫的码；
6. 依赖补齐（`qrcode`、`pycryptodome` 改为必装）；
7. 新增唤醒提示词模板：闲聊快答与任务做实分野、事实先核实、
   诚实红线、链接读原文规矩、ack 存回复全文；
8. 澄清主动推送的 24 小时会话窗口与失败回退策略；
9. 排查表与已知边界补全（静态图误会、重复回复、认领未释放等实测条目）。
